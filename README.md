# 宇宙余息 · Cyber Forge

手势驱动的熵、意识与宇宙记忆互动影像装置。用户只需一只手即可把混乱粒子锻造成星核；每次创造都会消耗维持封闭宇宙运行的压差，最终留下可下载、可分享的“个人星系档案”。

**Live experience:** https://zhangshuxiao1112-dotcom.github.io/cyber-forge/

## 完整体验

1. **待机吸引**：星空与微弱压力波纹展示项目命题。
2. **五秒校准**：采集手掌尺度与活动范围，全部阈值使用手掌宽度归一化。
3. **星核锻造**：单手捏合时产生聚合烟花和低频音效，张开时产生释放烟花和高频音效。
4. **打开星门**：先完成捏合—张开，再将完整手掌持续张开两秒，触发跨宇宙压力通道。
5. **个人成果**：生成几乎不重复的星云名称、三行原创科幻诗、现实天体映射、手掌星图数据、档案海报、二维码与约五秒星门影像。

## 手掌宇宙映射

- 掌宽决定天体的视觉尺度，小型掌面倾向创生之柱，大型掌面倾向仙女座大型星盘；
- 指尖展开度、径向对称性、关节点长宽比和手掌方向共同决定匹配结果；
- 支持仙女座、涡状星系、车轮星系、草帽星系、螺旋星云、创生之柱、船底座宇宙悬崖和蜘蛛星云八类现实原型；
- 不同原型使用不同关键点形状、色谱、旋臂、星环、尘埃盘、气体柱或丝状星云效果；
- 映射会写入最终报告，说明手部形态为何与该现实天体相似。

## 本地生成式宇宙报告

- 名称引擎组合东方天问、古典神话、时间旅行、太空歌剧、赛博梦境、异星文明和星海游戏等母题；
- 诗句由多层原创语料进行种子化组合，不复制小说、电影或游戏台词；
- 每次生成都会叠加手势数据、完成时间和浏览器安全随机熵，形成独立生成编号；
- 报告包含星云名称、宇宙身份、三行科幻诗、现实天体特点、匹配原因、手掌尺度/指距/对称度和灵感母题。
- 分享二维码只保存生成种子与量化手掌参数，扫描后在目标设备重新构建完整报告，避免长诗和说明文字超过二维码容量；旧版完整档案链接仍可读取。

现实天体特征参考 NASA Science 的星系与星云资料，包括 M31、M51、M104、车轮星系、螺旋星云、创生之柱、NGC 3324 和 30 Doradus。

## 视听系统

- 深空背景加入多层星云光带、引力透镜弧、遥远星系和手势视差；
- 张掌时在掌心生成与匹配天体一致的实时星系形态；
- 音效由多振荡器、频率滑移、滤波、延迟反馈和程序化噪声共同合成；
- 捏合、释放、校准、星门和归档分别使用不同的科幻声纹，不依赖外部音频文件。

## 摄像头与手势识别

- 点击“先测试摄像头与手势”进入独立验证页；
- 摄像头通过浏览器 `getUserMedia` 启动；
- 采用本地内置的 MediaPipe Hands 持续识别，不再请求已经失效的旧 TFHub HandPose 地址；
- 模型、WASM、TFLite 与运行脚本全部包含在程序包中；
- 测试页显示摄像头、21 个关键点、骨架、捏合比和张开度；
- 多只手同时出现时只保留置信度最高的一只，降低抖动和计算负担；
- 确认真实识别稳定后，再点击“启动锻造舱”进入目标体验。
- 完成一次锻造后点击“锻造另一个宇宙”，会复用仍然存活的识别链路；如果摄像头流、模型或帧循环已经中断，则自动重新启动并进入校准。

## 识别稳定性

- 拇指—食指距离除以掌宽，不再使用固定像素阈值；
- 捏合与松开采用不同阈值，形成迟滞区；
- 连续三帧确认，降低边界抖动；
- 关键点使用指数平滑；
- 优先使用 MediaPipe handedness 维持左右手身份；
- 完整张掌必须连续保持两秒；手掌离开画面或闭合后计时立即清零；
- 原始摄像头画面默认不显示、不上传、不保存。

## 展示模式

- 点击“启动锻造舱”启用真实摄像头手势；
- 点击“无需摄像头 · 体验演示”进入完整模拟流程；
- `F`：全屏；
- `R`：重置；
- `D`：从待机页直接进入演示；
- 右上角控制面板可切换声音、调试骨架与粒子密度。

## 一键运行

运行前只需安装 [Node.js 22 LTS](https://nodejs.org/)：

- **macOS**：双击 `启动-Cyber-Forge.command`
- **Windows**：双击 `启动-Cyber-Forge.bat`
- **Linux**：在项目目录执行 `bash 启动-Cyber-Forge.sh`

脚本会在首次运行时自动安装依赖，然后启动网页。浏览器访问：

```text
http://localhost:3000
```

真实手势模式需要允许浏览器使用摄像头；也可以点击“无需摄像头 · 体验演示”直接体验完整流程。

## 命令行运行

```bash
npm ci
npm run dev
```

`npm run dev` 会先通过跨平台 Node.js 脚本自动准备 MediaPipe 资源。手势模型、WASM 与 TFLite 文件随后从项目的 `public/mediapipe` 目录加载，不依赖 CDN、TFHub 或 Bash。

## GitHub Pages

推送到 `main` 分支后，`.github/workflows/deploy-pages.yml` 会自动安装依赖、从锁定版本的 `@mediapipe/hands` 准备模型文件、执行静态导出并发布到 GitHub Pages。首次部署需要在仓库 **Settings → Pages → Build and deployment** 中将 Source 设为 **GitHub Actions**。

仓库与 GitHub Pages 均为公开访问，不需要登录。真实手势模式通过 GitHub Pages 的 HTTPS 安全来源申请摄像头权限；访问者首次点击手势入口时，需要在浏览器中选择“允许”。

## 验证

```bash
npm run lint
npm test
```

自动测试覆盖归一化捏合、完整张掌、两秒保持时长、握拳/张掌/指向信号、手掌—天体分类、生成式报告稳定性与变化性、二维码紧凑编码与解码，以及部署产物的基础页面响应。

## 使用提示

- 推荐使用最新版 Chrome 或 Edge。
- 请保持一只手完整出现在画面中，距离摄像头约 0.6–1.5 米。
- 首次安装 npm 依赖时需要联网；之后手势运行使用项目内置模型。
- 摄像头画面默认不显示、不上传、不保存，只有在用户主动生成成果时才会导出互动视觉。
